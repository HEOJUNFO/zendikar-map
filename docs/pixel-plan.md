# 픽셀 아트 지도 (/pixel) 계획

사용자 결정 2026-11-07. 지금 지도(양피지 SVG)와 나란히, 같은 데이터를 픽셀 아트로 그린 지도를 따로 된 페이지 `/pixel` 로 만든다.
움직이는 효과는 [pixelfx](https://github.com/patch-gg/pixelfx)(MIT, Patch)로 그린다. 한 번에 다 하지 않고 아래 단계마다 사용자가 보고 정한다.

## 결정

- **D1 주소**: `/pixel`. 루트의 `pixel.html` → `src/pixel/main.tsx`. 라우터는 두지 않는다 (react-router 를 쓰지 않는다).
- **D2 따로 빌드**: `vite/pixel.config.ts` 가 지금 지도를 빌드한 `dist/` 에 덧쓴다 (`emptyOutDir: false`). 한 빌드에 진입점 둘을 두면 함께 쓰는 모듈이 공유 조각으로 빠져
  지금 지도의 진입 조각이 바뀐다 (`entry-check`·`load.mjs` 기준값). `pnpm build` = `tsc -b && vite build && vite build -c vite/pixel.config.ts`,
  Vercel 은 `vercel.json` 의 `buildCommand` 로 이 명령을 쓰고 `/pixel` 을 `/pixel.html` 로 다시 쓴다(rewrites). 개발 서버는 `vite.config.ts` 하나로 두 페이지를 낸다.
  `pixel/index.html` 꼴은 쓰지 않는다 (개발 서버가 끝 `/` 없는 `/pixel` 에 지금 지도를 낸다).
- **D3 지금 지도는 그대로**: S1–S7 은 지금 지도의 모듈을 고치지 않고, 순수한 데이터·기하만 가져다 쓴다 (`geo.ts`·`geometry.ts`·`src/data/*` 가운데 DOM 이 없는 것).
  지금 지도의 셈(`labels.ts`·`layoutHedrons` …)이 필요하면 **복사**해 쓰고, 나중에 함께 쓸 모듈로 빼더라도 옮김마다 커밋 하나로, `saga-regress`·`labels-diff`·`entry-check` 를 지키며 한다.
  S8 의 '픽셀 지도로' 링크가 처음으로 지금 지도의 번들을 일부러 바꾸는 커밋이다.
- **D4 범위**: 세계 지도의 페이즈 그림까지 지금 지도와 맞춘다. 지역 상세(자식 지도)는 픽셀로 그리지 않는다 — 지역 상세에 사는 대상은 패널에만 싣는다 (S9 에서 따로 정한다).
  확대에는 상한을 둔다 (한 픽셀 = 0.25 단위).
- **D5 설정 원칙은 같다**: CLAUDE.md 의 설정 원칙(공식 근거·`estimate`·`nameKo`·그 무렵 모습·한 곳은 한 번만 …)과 저장한 선호(추정 자리에 다른 표시 모양을 쓰지 않는다 — '추정'은 패널에만,
  카드 모아보기 화면을 두지 않는다)를 픽셀 지도에도 그대로 따른다. 데이터가 같으니 새 설정 주장을 만들지 않는다 — 데이터에 없는 지형·효과는 그리지 않는다.
- **D6 pixelfx**: 앱이 쓰는 코드는 고정 커밋(`a841596`, v0.3.0)을 `src/pixel/vendor/pixelfx/` 에 LICENSE·NOTICE 와 함께 복사한다 (S5 — 쓰는 효과만, 캐릭터 연기 `act`·`rig`·`actor`·`poses` 와 `gallery/` 는 빼고).
  `src/fx/index.js`(244개 전부)나 패키지 루트를 import 하지 않는다. `gallery/fonts` 의 Patch Pixel 글꼴은 MIT 가 아니라 쓰지 않는다.
  `tools/`(render·check·sheets …)는 `references/pixelfx`(`pnpm refs` 로 받는 작업대, git 제외)에서 돌려도 된다. pixelfx Claude Code 스킬은 프로젝트 범위로 설치했다
  (`.claude/settings.json` 의 `pixelfx@pixelfx`) — 스킬이 말하는 'pixelfx checkout' 은 `references/pixelfx` 다. 만든 효과는 검토한 뒤 복사해 넣는다.
- **D7 한 픽셀의 크기**: `?s=` 는 한 픽셀의 화면 크기(CSS px, 1·2·3), 기기 픽셀로는 정수로 반올림한다 (DPR 1.5 화면에서 픽셀마다 폭이 달라지지 않게). 배율은 정수 배율만 —
  소수 배율에서 픽셀이 고르지 않게 깨진다. `?view=x,y,k` 는 지금 지도와 같은 뜻이라 두 페이지를 오가도 같은 자리를 본다 (k 에 가장 가까운 단계로 맞춘다).

## 피할 것

- 처음 불러올 때 `src/data/index.ts` 를 import 하기 (검사가 돌고 약 550KB) — 패널을 처음 열 때 받는다.
- `useMapZoom.ts`(React·d3), `raster.ts`(`document.createElement`)를 Worker 나 Node 에서 쓰기. `geo.ts` 는 Node 에서 import 되지 않는다(JSON import) — 시험 도구는 JSON 을 읽어 `geometry.ts` 로 같은 고리를 만든다.
- 해안선을 pixelfx `poly()` 로 그리기 (픽셀마다 모든 꼭짓점을 본다 — `src/pixel/raster/fill.ts` 의 활성 변 채우기를 쓴다), pixelfx `font.js`(영어 대문자만).
- 화면 전체 `putImageData`(DPR 3 휴대폰에서 한 프레임 약 12MB), 상한 없는 `dt`(시뮬레이션 효과가 120Hz 로 따라잡는다), 소수 배율의 nearest-neighbour.
- 데이터에 근거가 없는 효과, 1282개 그림을 모두 손으로 찍기, 처음부터 지역 상세까지.

## S1 메모

- **S1 결정 (2026-11-07, 사용자가 추천대로)**: 팔레트 b(16비트) — 양피지(a)는 픽셀 크기에서 물빛과 땅이 흐려 보였다. 한 픽셀 2×, 물가 디더링. 기본값으로 두고 `?pal`·`?s`·`?shore` 시험 스위치는 남긴다.

- 칸 종류(바다·땅·숲·육지 안의 물)는 `fill.ts` 가 짝홀 규칙으로 채우고, 물가 띠는 3-4 챔퍼 거리(`world.ts`)로 센다. 얼룩 노이즈는 지도 좌표에 붙어 단계가 바뀌어도 같은 자리에 있다.
- u = 1 장(2400×1700)은 아직 주 스레드에서 한 번에 그린다 — Worker·타일은 S2.
- 글자는 시스템 고정폭 글꼴 (픽셀 글꼴은 S3 — 아래).

## S2 메모

- **S2 결정 (2026-11-07, 추천대로)**: 휴대폰도 데스크톱과 같은 깊이(한 픽셀 = 0.25 단위)까지. 확대 단계는 `[16, 8, 4, 2, 1, 0.5, 0.25]` — 한 걸음에 두 배,
  16 은 휴대폰 개관용. 계획의 'pixel 크기 2·3 을 번갈아' 대신 한 픽셀의 화면 크기는 S1 에서 고른 2× 로 고정한다 (단계마다 점 크기가 들쭉날쭉하지 않게).
- 타일은 256² 픽셀, 둘레 `HALO` 10 픽셀을 더 채워 물가 거리를 센다 (`world.ts` — 물가 띠는 8 픽셀까지만 쓴다). 무늬는 단계 격자의 칸 번호와 지도 좌표에서만 정해져
  타일을 어떤 차례로 그려도 세계 한 장과 바이트까지 같다 — `node scripts/qa/pixel-regress.mjs` (이음매·거꾸로 그린 차례), `--save`·`--compare <파일>` 은 타일 해시
  (기준선 `.qa-baselines/pixel-tiles-s2.json` — S4 처럼 그림을 바꾸는 단계는 다시 남긴다). Node 가 `geo.ts` 를 읽게 하는 모듈 훅은 `scripts/qa/pixel-hooks.mjs`.
- 한 픽셀이 1 단위보다 작은 단계는 지금 지도의 깊은 확대처럼 `deepRings()` 를 쓴다 (`src/pixel/rings.ts`).
- 그리기: Worker 몇 개(코어 수 − 1, 많아야 3)가 타일을 ImageBitmap 으로 만들고(`tiles/worker.ts` — OffscreenCanvas 가 없으면 RGBA 를 보내 주 스레드가 만든다),
  `tiles/store.ts` 가 LRU(데스크톱 256장·휴대폰 96장, 화면의 타일은 버리지 않는다)로 붙잡는다. 화면 크기 캔버스 하나에 기기 픽셀 정수 배율로 붙이고,
  아직 없는 타일은 더 거친 단계의 타일을 늘이거나(없으면 한 단계 고운 타일 넷을 줄여) 채운다. 요청은 화면이 바뀔 때마다 통째로 바꾼다 (가운데부터, 한 칸 둘레까지 미리).
  몸짓은 S1 의 것을 그대로 쓴다 — d3-zoom 은 들이지 않았다 (단계가 정수 배율이라 부드러운 확대가 없어 쓸 데가 없었다).
- 성능 (`node scripts/qa/pixel-perf.mjs [--desktop] [--cpu n] [--view x,y,k]`, 개발 서버 뒤): 한 방향으로 화면 폭의 0.8 씩 여섯 번 끌어 새 타일을 받는 길까지 잰다.
  CDP 의 CPU 제한은 Worker 에 닿지 않아('only supported for pages') 개발 서버의 `?tileslow=n` 으로 Worker 가 같은 타일을 n 번 그린다.
  휴대폰 390×844 DPR 3·CPU 4배(Worker 도 4배)에서 끌기 프레임 간격 p95 16.8ms, 그리기 한 번 p95 0.6ms, 타일 한 장 Worker 6–10ms(첫 장 약 40ms),
  끄는 동안 새 타일 4–20장, 붙잡은 타일 20–40장(5–10MB). 데스크톱 p95 16.7ms.
- 타일 창고는 그리기가 바라는 타일(화면·둘레·늘여 채운 타일)을 모두 붙잡는다 — 바라는 타일을 버리면 다음 그리기가 다시 청해 끝없이 다시 그렸다(5K 화면·`?s=1`, 검토 2026-11-07).
  상한(256·96장)은 화면 크기가 바뀌면 다시 정한다.

## S3 메모

- **S3 결정 (2026-11-07, 추천대로)**: 글꼴은 Galmuri11, 한글 크기는 그 설계 크기, 패널은 픽셀 지도에 맞춘 새 패널 (지금 지도의 양피지 패널을 다시 쓰지 않는다).
- 글꼴: Galmuri11 2.40.3(quiple, SIL OFL 1.1)에서 쓰는 글자만 남겨 `src/pixel/fonts/` 에 싣는다 — 라틴 6KB(늘), 한글 146KB(`unicode-range` — 한글이 나올 때만).
  Galmuri 는 예약 글꼴 이름이라 고친(줄인) 파일은 글꼴 안의 이름을 'Zendikar Pixel' 로 바꿨다 (`src/pixel/fonts/README.md`·`OFL.txt`). 다시 만들기는 `scripts/pixel/font.sh`.
  설계 크기는 CSS 12px(한 칸 = 1px — 글자 높이 11칸) — 계획의 '11px'는 이 크기를 말한다. 12·24px 로만 쓰고, 글자 폭은 글꼴에서 잰 표(`src/pixel/labels/advance.ts`, 생성물)로 센다.
- 첫 조각에는 이름과 자리만: `vite/pixelMarks.ts` 가 원본(`locations.ts`·`cards.ts`·`continents.ts`)에서 `virtual:pixel-marks`(약 21KB)를 뽑는다 (`src/pixel/marks/slim.ts`).
  패널의 글은 처음 고를 때 받는다 (`src/pixel/panel/data.ts` — 원본 약 115KB gz, 영어 보기는 사전 `base.json` 약 130KB gz 도). `src/data/index.ts` 는 부르지 않고 카드·장소를 잇는 셈만 같게 옮겼다.
  지금은 페이즈를 끈 지도의 것만 — 사가에 매인 대지 카드·페이즈 카드·양면 카드의 대지 면·바탕 지형 글·그 무렵 모습은 S4·S6·S7.
- 이름 배치(`src/pixel/labels/layout.ts`)는 `labels.ts` 와 ZendikarMap.tsx 의 차례(대륙명 → 중요한 장소의 오른쪽 자리를 비운 지역 이름 → 장소·카드 이름 → 남은 자리의 지역 이름)를 복사했다.
  단계마다 화면 px/단위가 하나라 tier 안의 배율 범위가 없다. 단계마다 보이는 prominence 는 지금 지도의 tier 경계를 옮긴 [3, 3, 3, 2, 1, 0, 0], 카드 기호는 가장 먼 단계에 두지 않는다.
  대륙명은 한 픽셀 ≥ 4 단위의 단계에만 (가장 먼 단계 12px, 그다음 24px). 지역 이름은 지도에서 24px 를 넘게 커지면 24px.
  아직 비키지 않는 것: 섬 크기에 따른 기호 늦추기(지금 지도의 `glyphFrom`), 헤드론·바탕 지형·페이즈 그림·지역 상세 (그것을 그리는 단계에서).
- 기호는 7×7 픽셀 그림에 밝은 한 픽셀 테두리(`src/pixel/marks/sprites.ts`), 한 기호 픽셀 = 화면 2px. 카드 표시는 장소 표시와 같은 기호, 추정 자리도 모양이 같다.
  기호·이름은 캔버스 위의 DOM 층이고 지도 원점에 붙어 끌기는 층의 transform 만 바꾼다 (끌기 p95 그대로 16.8ms). 기호 단추를 누르게 하려고 몸짓의 붙잡기(pointer capture)는 누른 자리에서 8px 넘게 벗어난 뒤에 한다 (손끝이 조금 밀린 누름도 고르기).
- 고른 것은 지금 지도와 같은 주소(`#장소id`·`#card/id`·`#continent/id`) — 장소와 하나인 카드는 장소 패널을 연다. 처음 연 주소에 `?view` 가 없으면 그곳으로, 이름이 보이는 단계까지 확대해 간다.
- 시험: `node scripts/qa/pixel-labels.mjs`(Node — 모든 이름이 en·ko 로, 한 픽셀 크기 1·2·3 × DPR 1·1.5·2·3 에서 어느 단계에선가 자리를 받는지, 기호가 모두 어느 단계에선가 그려지는지,
  `nameKo` 가 데이터에 있을 때만인지, 단계마다 이름끼리 겹치지 않는지), `node scripts/qa/pixel-marks.mjs`(개발 서버 뒤 — 데스크톱·휴대폰 터치에서 기호 누르기·기호에서 시작한 끌기·# 주소·패널 초점·영어 글·Esc·Tab 이 그려진 표시를 모두 지나는지·장소와 하나인 카드 주소).
- 단계마다의 prominence 문턱은 한 픽셀 2×(기본값)에서 지금 지도의 tier 와 맞는다 — `?s=1|3` 시험 스위치에서는 어긋난다 (시험 스위치라 그대로 둔다).
- 검토(2026-11-07)로 고친 것: Tab 으로 화면 밖 기호에 닿으면 브라우저가 지도 칸을 스크롤했다(`overflow: clip`), 고른 이름이 S2 의 눌린 단추 규칙에 덮여 읽히지 않았다,
  `#card/<지도에 있는 장소와 하나인 카드>`(Eye of Ugin)가 그곳으로 가지 않았다(`virtual:pixel-marks` 의 `cardPlaces`), 세계가 화면에 다 드는 개관에서 패널 밑의 기호를 비키지 못했다
  (지도가 화면보다 작을 때 가운데에 묶던 것을 풀었다), 잘못된 `%` 의 # 가 페이지를 멈췄다, 없는 id 가 빈 패널을 열었다. 그 밖에 대륙 패널의 대륙 카드·장소 차례, 두 면이 모두 대지인 카드의 '양면 카드' 칸,
  DPR 1.5 의 기호 흐림, ⌂(글꼴에 없어 7×7 픽셀 그림으로). 모두 `pixel-marks.mjs` 가 본다.

## 확대·축소 다듬기 (S3 뒤, 2026-11-07)

- 사용자: '줌인 줌아웃할 때 렉이 좀 있는 듯'. 재어 보니(휴대폰 CPU 4배·Worker 4배, 데스크톱) Worker 타일(256² 한 장 0.7–3.9ms)과 `draw()`(≤2.4ms)는 원인이 아니었다.
  원인은 셋이었다: 단계가 한 번에 바뀌어 두 손가락을 모으는 동안 반응이 없었고(손가락 거리 1.6배에서야 두 배로 튀었다 — 모으기와 벌리기의 단계 수도 달랐다),
  기호 층이 화면 밖 기호까지 단계마다 다시 칠했으며(휴대폰 칠하기 11–21ms), 두 단계 넘게 빠르게 축소하면 늘일 타일이 없어 빈칸(페이지 색)이 났다.
  개발 서버의 React 는 렌더가 2–3배 느려(jsxDEV) 확대 성능은 빌드(`pnpm build && pnpm preview`, 주소에 `?perf`)에서 잰다.
- 이어 그리기: 단계를 바꾸면 화면은 지금 보이는 배율에서 새 단계까지 160ms(`ZOOM_MS`, 움직임 줄이기에서는 바로) 이어 그린다 — 늘 붙잡아 둔 개관(한 픽셀 = 8 단위, 타일 두 장),
  지금 단계, 움직이기 전 단계의 타일을 거친 것부터 그 배율로 겹쳐 그린다. 끝 프레임은 전과 같은 정수 배율이다. 두 손가락·트랙패드(ctrl+휠) 확대는 배율을 그대로 따라가고 손을 떼면 가장 가까운 단계로 간다.
  휠은 쉬면 남은 몫을 버리고 한 칸(50)에 한 단계, 이어 그리기 한 번에 하나까지. 움직이는 동안 기호 층은 숨긴다 (이름은 화면 크기가 고정이다).
- 빈칸: 더 고운 단계는 셋까지 줄여 얹고, 개관 단계를 늘 붙잡아 둔다. 단계를 바꾼 뒤 180ms 는 한 칸 둘레를 미리 청하지 않는다 (지나가는 단계의 둘레 타일이 마지막 단계를 늦췄다).
- 기호 층: 화면 가운데가 든 칸(화면 반 폭)에서 사방 화면 한 장 밖의 기호·이름은 그림·글자 없는 1px 빈 단추로만 둔다 — Tab 으로는 닿고 초점을 받으면 그곳으로 옮겨 다시 그린다.
- 그 밖에: `draw()` 는 단계를 ref 에서 읽는다(React 가 다시 그리기 전에 타일이 와도 새 단계·새 가운데로), 확대 단추는 단계 글 뒤에 두어 움직이지 않는다,
  `replaceState` 는 잠잠해진 뒤 250ms 에 한 번, Worker 는 첫 타일 뒤 깊은 단계의 고리를 미리 만든다. 타일은 바이트까지 그대로다 (`pixel-regress --compare`).
- 시험: `node scripts/qa/pixel-zoom.mjs`(빌드 미리보기 뒤 — 확대 중 프레임 간격·긴 작업·빈칸·첫 반응·또렷해질 때까지).
