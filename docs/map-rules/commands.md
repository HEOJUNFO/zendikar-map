# 명령어

> `CLAUDE.md` 에서 옮긴 전문이다(2026-11-10 — 세션마다 실리는 양을 줄이려고 나눴다). 글은 옮기기 전 그대로다. 규칙을 새로 정하거나 고치면 이 파일에 적고, `CLAUDE.md` 의 요약이 달라질 때만 그 요약도 함께 고친다. 코드 주석의 "CLAUDE.md …" 는 이 파일을 가리킨다.

- `pnpm dev` — 개발 서버
- `pnpm build` — 타입체크 + 빌드
- `pnpm lint`
- `python3 scripts/geo/extract_geo.py` — 팬 지도에서 해안선·숲·내해를 다시 추출하고 대륙 배치(`LAYOUT`)를 적용 (opencv-python, numpy 필요). 팬 지도 좌표를 새 좌표로 옮길 때는 같은 폴더의 `relocate.py`
- `node scripts/figures/to_ts.mjs > src/map/figures.ts` — 페이즈 그림 원본(`scripts/figures/art/<카드id>.js`)에서 다시 만들기 (그림은 묶음마다 `src/map/figures/<world…|지역 상세 id>.ts` 에, 그림마다의 상자·묶음은 `src/map/figures/frames.json` 에 함께 쓴다). 원본은 작업대 `scripts/figures/index.html?ids=…`(지도 배율별 미리보기)에서 보며 고치고, 화풍은 `scripts/figures/STYLE.md`
- `node scripts/childmaps/to_ts.mjs` — 지역 상세 원본(`scripts/childmaps/art/<id>.js`, 공통 그리기 도구 `kit.js`)에서 `src/map/childmaps/<id>.ts` 와 그림 크기 목록 `src/map/childMapSizes.ts` 를 다시 만들기. 원본은 `pnpm dev` 뒤 `?phase=1&childsrc=1`(원본을 바로 읽는다)에 그 장소 패널의 '가까이 보기'(또는 `&view=x,y,k`)로 가 보며 고치고, 그 범위의 세계 지도 맥락(해안·장소·헤드론·세계 지도 그림을 그림 좌표로, 더 깊은 지역 상세는 부모 그림까지 — 그림이 아직 없으면 `--scale 10`, 옮긴 부모 그림 미리 보기는 `--svg <파일>`)은 `node scripts/childmaps/context.mjs <id>`, 검사만 하려면 `node scripts/childmaps/to_ts.mjs --check [id …]`(더 깊은 지역 상세는 부모와 맞는지도 본다), 화풍은 `scripts/childmaps/STYLE.md`
- `node scripts/qa/shots.mjs <폴더> 이름='?view=x,y,k' …` — 스크린샷 (`--w --h --mobile --wait`) · `node scripts/perf/measure.mjs [--phase n] [--cpu 4]` — 배율별 화면 안 요소 수와 끌기·휠 확대 중 프레임 간격 (둘 다 `pnpm dev` 뒤). 첫 로딩(느린 망의 FCP·지도·페이즈 그림이 나온 때·조각별 도착·긴 작업·바이트)은 `node scripts/perf/load.mjs [--phase n] [--mobile]`, 어느 함수가 시간을 쓰는지는 `node scripts/perf/profile.mjs [--phase n] [--view x,y,k] [--incl=함수,…]` (둘 다 `pnpm build && pnpm preview` 뒤 — `--minify false` 빌드면 함수 이름이 읽힌다)
- 측정·스크린샷용 headless Chrome 은 **반드시 `scripts/qa/chrome.mjs` 의 `launchChrome()`** 으로 띄우고 끝나면 `await chrome.close()`. Chrome 을 직접 spawn 하지 않는다 — 예전 스크립트가 오류·타임아웃 때 Chrome 을 못 닫아 수십 개(15GB)가 쌓인 적이 있다. `launchChrome()` 은 파이프로 node 와 이어 node 가 죽으면 Chrome 도 꺼진다. 남은 것은 `pnpm chrome:reap`(`scripts/qa/reap-chrome.sh`, 훅이 세션 시작·턴 끝마다 자동 실행)이 부모 잃은 headless Chrome 과 10분 넘게 안 쓴 프로필 폴더를 치운다
- 시점별 지도 확인: `node scripts/qa/timeline-check.mjs [--expect 보이는 시점이나 모든 시점의 카드 수]`(시점마다 카드 수, 검사 V1–V6·V11(빈 시점의 까닭, T5 부터는 카드마다의 결정), 숨긴 시점의 남은 결정 수(지금 숨긴 시점은 없다 — T5·T6 의 결정은 모두 정했다), 시점별 그림 묶음 표가 낡았는지 — Node 만), `node scripts/qa/labels-check.mjs [--time 1,2,3,4,5,6] [--lang en,ko]`(그림 때문에 사라진 이름 — `pnpm dev` 뒤), `node scripts/qa/saga-regress.mjs --save <폴더>`(main 에서 — 기준선은 저장소의 `.qa-baselines/<도구>-<커밋>`(git 제외)에 남긴다. 세션 임시 폴더는 사라진다) · `--compare <폴더>`(사가 보기·끔 화면 72개(단계 0–8 × 고정 화면 8)와 생성물이 main 과 바이트까지 같은지 — `pnpm dev` 뒤, `--static-only` 면 생성물만. 사가3 의 L6 은 열리면(`phases` > 0) 함께 뜨고, 그린 것이 아직 없으면 L0 와 같아야 한다 — 사가4 의 L7·L8 도 같다(main 뒤 단계라 L7·L8 기준선은 따로 남긴다). main 뒤 단계의 생성물(`-6` 그림 묶음·frames 항목, 지역 상세의 `phase6` 문과 그 단계 카드의 `subjects` 줄)은 지우고 견준다 — 스크립트 머리 주석. 기준선에 없는 L6 은 견주지 않으니 `--save <폴더> --only L6-…` 로 따로 남긴다). `figures/to_ts.mjs` 는 V7·V8(잃은 바탕·그림 겹침), `childmaps/to_ts.mjs --check` 는 V9·V10(빈터·손그림 걸림·낡은 시점 열쇠)에서 멈춘다 — 새로 이어 그린 시점의 자리를 아직 고르지 않은 단계에는 `TIMELINE_LAYOUT=warn` 으로 겹침(V8)과 자리 검사([15]–[18])를 경고로만 보이고 만든다(숨기지 않는다, 잃은 바탕·열쇠 검사는 늘 멈춘다). 성능·QA 도구(`load.mjs`·`measure.mjs`·`profile.mjs`·`period-check.mjs`·`svgdiff.mjs`·`context.mjs`)는 `--time t`, 스크린샷은 `shots.mjs` 에 `'?time=t&view=…'`
- 이름 자리 비교: `node scripts/qa/labels-diff.mjs --save <폴더> [--base 주소] [--root <트리>]`(앞 트리 — main 의 worktree 를 따로 띄워 `--root` 로 — 에서) · `--compare <폴더>`(끔·사가 단계 모두·열리는 시점 모두 × tier × en·ko 에서 기준에 자리를 받은 이름이 지금 사라졌으면 1, 이름 쪽·지역 이름 자리가 바뀐 것은 목록만, 기준 뒤에 새로 생긴 카드의 이름은 세지 않는다. 그림을 받지 못해 이름이 통째로 빠진 보기(그림을 그리는 보기 — 기준에도 그림 이름이 있는 — 에 그림 0장, 또는 그림도 기준의 반에 못 미치면서 그림 이름·모든 이름이 기준의 반도 안 된다 — 기준이 보기마다 그림 수를 남기니 그림은 다 왔는데 이름만 빠졌으면 사라진 이름으로 센다)는 더 오래 기다려 두 번까지 다시 읽고, 그래도 무너지면 사라진 이름이 아니라 '믿을 수 없음'(종료 코드 3 — 시험은 `--block-figures L4-ko:1`). 페이지가 오류를 던진 보기는 다시 읽지 않고 실패(1) — `pnpm dev` 뒤. `--views off,L3,T2` 로 보기 몇 개만, `--track card:<id>,…` 로 새 표시의 이름이 tier 마다 어느 쪽에 자리를 받는지 — 기준 트리에 `?labelcheck` 의 `sides`·`areaAt` 가 없으면 ZendikarMap.tsx 의 그 두 줄을 붙여 띄운다). 새 표시가 기존 이름의 자리를 가져가는 것은 labels-check·saga-regress 가 보지 못하니 마커·그림을 더하면 이것으로 본다
- 페이즈 바탕(그 무렵 모습) 확인: `node scripts/qa/gates-test.mjs`(페이즈 문 셈 — 약 4초), `node scripts/qa/period-mark-test.mjs [--base 주소]`(자리 없는 장소의 표시 바꿈·떨어진 하늘거주지 기호 — 픽스처, `--base` 면 그림이 비우는 원 안에 드는지도), `node scripts/qa/period-check.mjs`(개발 서버에서 단계마다 다시 이은 지형이 바로 셈한 것과 같은지), `node scripts/qa/svgdiff.mjs`(같은 화면의 `?noperiod=1`(DEV) 과 견줘 페이즈 바탕 밖 차이가 없는지 — 사가4 의 단계 7·8 처럼 장소 표시·이름·기호 상자를 가려야 하는 단계는 상자 JSON 을 함께 준다: `node --input-type=module -e "import('./src/data/periods/qa.ts').then((m) => console.log(JSON.stringify(m.periodQaBoxes(), null, 1)))" > boxes.json` 뒤 `node scripts/qa/svgdiff.mjs off.svg on.svg --level 8 --boxes boxes.json` — off·on 은 같은 화면의 `?saga=4&phase=2&noperiod=1&view=…` 와 `?saga=4&phase=2&view=…` 의 `svg.zendikar-map` outerHTML), `node scripts/qa/entry-check.mjs`(첫 조각에 페이즈 바탕이 끌려 들어오지 않았는지). 지역 상세는 `node scripts/childmaps/context.mjs <id> --level n`(그 단계에 그려지는 것만)·`--svg <파일> --level n`(미리 보기). 성능 도구는 `--saga s --phase n`
- 패널 영어: 화면 글은 `src/i18n/messages.ts`(en/ko 타입 묶음), 데이터 글(설명·근거·추정 — 한국어 원본)은 한국어 문장마다의 영어 사전 `src/i18n/en/<묶음>.json` — base(장소·대륙·대지 카드·지역 상세 안내·바탕 지형·페이즈 바탕·범례 글 — 범례의 페이즈·시점 설명은 `src/data/notes.ts`, 범례의 이름표는 `messages.ts` 의 `legend`)는 영어 보기에서 한 번 받고(`src/i18n/dicts.ts`), phase<n>(그 페이즈 카드)은 통째로 받지 않고 `vite/phaseData.ts` 가 카드 한 장의 조각(`?card=`)에 그 카드 문장의 영어만 `EN` 으로 싣는다(모으는 칸은 `src/i18n/collect.ts`). 한국어 원본을 고치면 그 문장은 영어 보기에서 한국어로 남으니 데이터 글을 고친 뒤에는 `node scripts/i18n/extract.mjs --check`(남은 문장이 있으면 1)로 보고, `--todo <폴더> --set <묶음>` 으로 옮길 묶음을 만들어 `scripts/i18n/BRIEF.md` 대로 옮긴 뒤 `node scripts/i18n/merge.mjs --set <묶음> <파일…> [--prune]` 으로 넣는다(카드의 영어 이름·플레이버는 `node scripts/i18n/card.mjs <카드id>`). 넣은 뒤 `node scripts/i18n/audit.mjs [묶음…] [--scryfall <카드 글 모음>]` 으로 빠진 문장·같은 문장 두 번·알려진 오역·저장소와 Scryfall 에 없는 인용을 본다. 공식 영어 원문(카드 플레이버·기사)을 한국어로 인용한 문장은 원문 그대로 되돌리고, 원문을 확인하지 못하면 따옴표 없이 풀어 쓴다. 데이터 글의 페이즈 번호는 이어 센 번호(페이즈4) 대신 화면 표기(사가2 페이즈1)로 쓴다
