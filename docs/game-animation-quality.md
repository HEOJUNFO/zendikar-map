# 1막 실제 리깅·애니메이션 완료 조건

2026-10-16 사용자 요구: 임시 휴리스틱 연출이 아닌 실제 몹 리깅·애니메이션을 게임에 반영한다. 목표는 대형 게임사의 크리처 애니메이션 수준이다. **자동 생성 성공·본 개수·빌드 통과만으로 이 품질을 달성했다고 표시하지 않는다.**

대상은 현재 지도 1막 ZEN의 River Boa, Living Tsunami, Timbermaw Larva, Sky Ruin Drake, Roil Elemental이다. 최초 생성한 5개 GLB는 정적 bind mesh였고, 이후 실제 Studio/Blender 골격·스킨과 총 29개 DCC 클립을 제작했다. 현재 소비 경로는 실제 WebGPU 게임과 `/game/quality/`다. 실제 리깅 구현과 아래 품질 기준의 전체 충족은 구분한다.

## 허용하지 않는 대체

- 전체 메시의 상하 이동·회전·크기 변화, 가짜 흔들림, 소수 정점에 사인파를 붙이는 것을 몹 애니메이션으로 취급하지 않는다.
- 예전 박쥐·사족 드래곤·인간형 리그를 새 드레이크·뱀에 그대로 붙이지 않는다. 실제 새 몹의 관절과 형상에 맞춰 검토한다.
- 물·탁류 정령을 인간형 돌 골렘 골격으로 바꾸지 않는다. 비인체형 변형 리그·실제 변형 캐시가 필요하다.
- 본·웨이트·클립이 없거나 검수에 실패하면 정적 메시로 조용히 폴백하여 완성처럼 배포하지 않는다.

원본 GLB·편집 가능한 DCC 파일·스켈레톤 계층·inverse bind·정규화한 스킨 웨이트·클립 및 이벤트를 보존한다. 게임용 변환은 원본의 실제 데이터를 읽고, 제출 옵션이나 추측한 본 좌표로 성공을 주장하지 않는다.

## 검증

- 모든 실제 소비 정점에 유효한 본 영향이 있고 웨이트 합이 1이다. UV seam의 같은 위치는 연속된 웨이트를 유지한다. 무가중치 정점·NaN·범위 밖 본·누락 클립은 실패다.
- bind pose를 복원하면 원본 표면으로 돌아온다. 런타임 CPU 기준 변형과 실제 GPU 저장/제출 결과를 비교한다.
- 대기·이동·공격·피격·사망의 실질적인 관절/표면 변형을 확인한다. 전체 물체의 rigid transform만 제거하면 움직임이 사라지는 결과는 통과시키지 않는다.
- 이동 속도·루트 모션·접지, 발/배/꼬리의 미끄러짐, 날개·턱의 관통, 공격 예고/실제 명중 이벤트, 클립 전환과 사망의 종료 상태를 실제 게임에서 확인한다.
- 정면·측면·후면, 여러 동시 개체, 서로 다른 시작 위상, 프레임률 변화와 일시정지/재생을 확인한다. 같은 프레임·조명·소비 파일 해시로 캡처한다.
- 성능은 실제 다수 몹 장면의 CPU/GPU/프레임 시간을 측정한다. 리그를 제거하거나 정적으로 바꿔 성능 목표를 맞추지 않는다.

기존 엔진의 실제 스키닝 경로를 재사용한다. 지원 본 수·클립 재생·독립 개체 팔레트가 부족하면 실제 데이터에 맞게 확장하고 검증한다. 자동 리깅이나 이동 프리셋이 지원되어도 공격·피격·사망·보스 패턴까지 완료됐다는 뜻은 아니다.

## 비용·진행 cutoff

- 기존 승인한 정적 모델 생성 5회는 완료했다. 추가 리깅·애니메이션 비용은 여기에 포함됐다고 가정하지 않는다.
- 웹 JWT 직접 HTTP로 무료 rig precheck를 먼저 조회한다. 실제 지원 종·리그 종류·프리셋을 확인한 뒤 추가 유료 작업을 구체적인 수량으로 확정한다.
- 실패/불명 결과를 자동 재제출하지 않는다. Blender 진단·Studio 썸네일은 실제 게임의 스키닝 검증을 대신하지 않는다.

## 2026-10-16 실제 구현·검증 cutoff

- 승인한 추가 유료 작업 정확히 3회 완료: 보아 리깅 20본, 보아 이동 소스, 드레이크 리깅 51본. 보아 이동 원본은 배가 바닥 아래로 9.7cm 들어가 사용을 제외하고 보존했다. 게임 이동은 실제 체인을 다시 키프레임으로 제작했다. 유충 13본, 해일 12본, 탁류 정령 16본은 직접 제작했다.
- 다섯 종의 idle/move/attack/hit/death 및 보스 패턴 4개를 60Hz 골격 행렬에서 구웠다. ZKSK는 실제 8영향 웨이트, `.rig`는 계층/inverse bind다. 엔진 본 한도는 128이며 개체별 팔레트·실제 이동 거리 기반 위상·전환·사망 유지/중력을 구현했다.
- 원본 메시·UV는 보존했다. 바인딩 프록시의 미세 UV seam을 원본 정점 ID로 연결하고 실제 웨이트를 다듬었다. 잘못된 단단한 보정을 연결된 바람 표면에 강제하던 문제를 제거했다. 보아 사망은 실제 7본 IK 목표를 쓴다. 해일 사망의 13.5cm 바닥 관통을 수정했다.
- 모든 60Hz 프레임에서 원본 정점 전체의 Blender/DQS 오차, 정규화·UV seam, rigid motion 제거 후 변형, 접지 및 간선 늘어남을 측정했다. 실제 WebGPU 렌더 캡처, 뷰어 제출 상태, 생산 셰이더와 공유하는 DQS 함수의 GPU readback/독립 CPU 비교는 `build/act1-overhaul/`에 소비 파일 해시와 보존한다.
- 이 cutoff에서 남았던 약 3cm 평면 접지 관통은 아래 2026-10-17 보정으로 해소했다. 이 cutoff의 보스 사체 AABB 판정은 아래 후속 보정으로 교체했다. 전수 자가 관통 검사, 정밀 관절/표면 충돌, 복잡한 지형·여러 프레임률에서 접지·이동·전환 검수는 계속 진행한다. 물/바람은 불투명 표면의 변형 리그이며 유체 시뮬레이션이 아니다. AAA 품질 완료는 선언하지 않는다.

## 2026-10-17 지속 품질 목표 · 평면 접지 보정

- 사용자 요청으로 지속 목표를 활성화했다. 기존 원칙·세계관·추가 유료 제출 승인 한도를 유지하며 실제 결함을 수정하고 검증한다. 빌드나 본 개수로 목표를 완료 처리하지 않는다.
- `solve-act1-ground-contacts.py`는 실제 정점 전체의 정규화 DQS 접촉 Jacobian으로 최소 관절 이동 QP를 푼다. 루트 관절은 변수에서 제외한다. 원본 `control-rig.blend`와 IK는 보존하고, 평가된 동작을 `ground-rig.blend`로 구워 제약을 이중 적용하지 않는다. 모든 프레임의 루트 행렬 보존도 검사한다.
- 접촉 스킨 간격은 0.5mm다. 원본에서 관통하던 10개 독립 fixture는 실제 런타임 바이너리에서 red→green을 남긴다. DCC 3,546프레임과 게임 캐시의 240Hz 보간 14,097개 시점을 검사했다. Root lift·메시 축소·정점 직접 이동으로 덮지 않는다.
- 뼈대 팔레트를 섞던 기존 전환에서 유충이 약 0.18mm 관통하는 별도 결함을 발견했다. 전환 중에는 두 실제 스킨 표면 결과를 볼록 결합한다. 두 표면이 같은 지지 평면을 지키면 전환 표면도 이를 지킨다. 각 리그는 여전히 최대 128본이며, GPU 팔레트는 현재/이전 두 세트를 싣는다. 정상 재생에서는 한 세트만 계산한다.
- 빌드·게임 검사 73개, 실제 WebGPU의 원래 29개 클립 및 전환 30개(합계 59개 GPU readback 비교)가 통과했다. 원시 자료와 실제 제출 캡처는 `build/act1-polish/`에 보존한다.
- 재생성 순서: 원본 DCC 저작 → 접촉 solve → `check-act1-deformation.py -- --ground --strict-ground` → `export-act1-rigs.py` → `check-act1-ground-cache.py` → `pnpm rig:test` → 통합 빌드와 실제 GPU 검증. 원본 DCC 해시가 바뀌면 오래된 접촉 solve의 export를 거부한다.
- **열린 작업:** 중단/피격 때 실제 직전 동작에서 이어지는 전환, 자가 관통, 경사·계단·벽 접촉, 실제 이동의 미끄러짐 및 최종 동작/성능 검수. 목표는 계속 활성 상태다.

## 2026-10-17 실제 중단 포즈의 위치 연속성

- 공개 World의 보스 공격 중 발사로 33.1377cm 표면 튐을 재현했다. 피격/사망 시작을 임의의 이동 포즈와 섞던 코드를 제거했다. 실제 직전 포즈와 기존 혼합 가중치를 고정 틱 상태에 기록하며, 새 목표를 중단한 시점의 현재 표면에서 시작한다. 종별 프레임·이벤트·보폭은 실제 디코딩한 클립의 작은 프로필로 전달한다.
- 이전 포즈의 만료 시각은 재피격에도 연장하지 않는다. 정수 틱에서 최대 8개 이전 포즈와 현재 포즈가 필요하며, 포즈 퇴출이나 메시 전체 복제 없이 유한한 볼록 혼합을 유지한다. 같은 틱에 다시 중단해도 가중치가 0인 새 목표를 과거로 추가하지 않는다. 방향 전환의 루트 yaw도 이전 포즈에 보존한다.

- 일반적인 뼈 끝점 IK는 배 아래 스킨을 바닥으로 밀어 넣어 기존 10cm 보정 한계를 넘었다. 한계를 늘리지 않았다. `solve-larva-skin-contacts.py`는 실제 DQS 정점 전체의 높이, 원래 머리 영역의 높이/앞쪽 위치, 실제 삼각형 쌍의 분리 조건을 제약으로 푼다. 4개 관절의 X/Z 회전 8자유도만 바꾼다. 루트·관절의 로컬 이동 채널·메시 정점 직접 수정은 없다. 순수 전진 운동학과 실제 DCC 행렬의 최대 차이는 2.65×10⁻⁷이었다.
- 초기의 한쪽 평면 보존 제약은 불필요한 곡률 제한을 만들었다. 실제 삼각형의 법선 2개와 모서리 교차축 9개의 분리축 판정으로 교체했다. 독립 전역 표면 감사에서 얻은 29쌍을 제약에 넣고, 그 쌍에 국한하지 않는 전체 삼각형 감사로 결과를 다시 확인했다. 머리 목표 높이는0.65m, 접촉 간격은0.5mm다. 최적화는 공식 [SciPy1.11.4 SLSQP](https://docs.scipy.org/doc/scipy-1.11.4/reference/optimize.minimize-slsqp.html)를 쓰며, 이는 오프라인 저작 도구의 의존성이다.
- 검토한 곡선은 `death-contact-curve.json`, 접촉 쌍은 `death-contact-pairs.json`이다. `larva_contact.py`는 원본 정점/삼각형, 실제 웨이트, bind 계층, 오브젝트 변환과 원래 행동 채널의 서명을 모두 확인한다. 빠진 서명·다른 기하·누락 프레임·루트 대상 변경·비유한 회전은 소스를 바꾸기 전에 거절한다. 새 저작에서 원래 바이너리와 동일한 모델/스킨/클립 재생성을 확인했다. 잘못된 접촉 삼각형 인덱스도 실패한다.
- 독립 런타임 회귀는 머리 스킨이 최소20cm 내려오면서 접지하는 것을 검사한다. 기존 생산 입력에서 실패, 현재 입력에서 통과했다. 기존 전체 표면 회귀도 그대로 유지하며 240Hz 1,709시점·대표 전환68개에 새 proper crossing이 없다. DCC 431프레임·240Hz 접지, 루트 행렬 보존, 필수 리그 검사16개와 통합 게임 검사79개가 통과했다. 실제 GPU 비교84건·품질 뷰어 제출51건·PNG16장·UI 사망 녹화를 갱신했다. 현재 증거는 `build/act1-larva-contact/evidence.json`이다.
- **ceiling:** 이 저작 곡선의 지지면은 평면이다. 벽에서 사망하거나 계단/경사에 걸친 사체를 환경에 맞추는 런타임 접촉은 검증되지 않았다. 연속 속도(C1)와 최종 동작 시각 검수도 별도 전체 목표에 남아 있다. 평면 사망 보정을 모든 지형의 사망 완료나 AAA 승인으로 확대하지 않는다.

재생성은 기존 `author-act1-control-rigs.py`에서 검토 곡선을 함께 적용한다. 새 기하/웨이트를 저작할 때는 `--skip-death-contact-curves`로 별도 baseline을 만든 뒤 아래처럼 다시 푼다. 결과를 생산 파일에 연결하기 전에 전체 접지/표면/DCC/실제 렌더 검사를 수행한다.
